# Screening dan Input Halaman Authenticator Verification

## Prerequisites

- Mode: FE+BE.
- Seeding (hook `before`, lewat API oleh akun aktor Total Control (Global Settings) `totalControlGlobalSettings_automated_{namaCompany}@qwertysystem.net`, kredensial `Spectra.env.GS_TC_PASSWORD`): tujuh user profil NEWDEVE (Tabel Data Uji Pre-setup #5: Activated, Active ON, sudah pernah login sukses di web dari browser uji A (device dikenali), login terakhir dari IP uji Jakarta (ID), logout web terakhir kurang dari 30 hari, Authenticator sudah terdaftar dengan secret yang diketahui aplikasi authenticator uji), password `Spectra.env.MFA_PASSWORD`, email bersuffix per run:
  - TC-AUTH-MFA-05: `Rizky Pratama` (`rizkypratama+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-06: `Nur Hidayati` (`nurhidayati+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-15: `Teguh Wibowo` (`teguhwibowo+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-08: `Putri Anggraini` (`putrianggraini+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-101: `Hendra Rahmawati` (`hendrarahmawati+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-103: `Teguh Rahmawati` (`teguhrahmawati+{runId}-009@qwertysystem.net`)
  - TC-AUTH-MFA-102: `Lina Rahmawati` (`linarahmawati+{runId}-009@qwertysystem.net`)
- Hook `after`: hapus ketujuh user dan tutup semua jendela privat. Pembersihan tidak berasumsi seeding berhasil penuh.
- Akun yang dipakai: tanpa login (halaman publik; tidak ada sesi aktif di browser) untuk semua TC. Tiap TC setelah TC pertama dimulai di jendela privat baru; TC pertama berjalan di browser awal; browser awal dan tiap jendela privat tanpa ID device tersimpan, dikenali sebagai browser uji B. Login dari IP uji Jakarta (ID) hanya memicu MFA karena device baru. Semua user berprofil NEWDEVE, jadi tiap login Password melewati Choose Verification Method tanpa layar Confirm to Continue.
- Environment variable: `GS_TC_PASSWORD`, `MFA_PASSWORD`. Password tidak ditulis di spec atau fixture.
- Kemampuan teknis: jendela privat; reCAPTCHA mode uji di environment; mail-catcher lingkungan uji untuk membaca kode OTP login (TC-AUTH-MFA-06); aplikasi authenticator uji (TOTP: SHA-1, 6 digit, periode 30 detik) yang memegang secret tiap user seeding untuk menghasilkan kode valid (TC-AUTH-MFA-102); clipboard dan Ctrl+V di browser (TC-AUTH-MFA-102); navigasi keyboard (tombol Tab, Backspace) dan indikator fokus (TC-AUTH-MFA-15, 101); pemantau request jaringan untuk memastikan tidak ada request verifikasi (TC-AUTH-MFA-08, 101, 102).
- Kemampuan teknis, seeding state BE per user: status Activated dan Active ON, trusted device ber-ID device browser uji A (device dikenali), lokasi dan waktu login terakhir dari IP uji Jakarta (ID), logout web terakhir kurang dari 30 hari, consent sudah disetujui sehingga tanpa layar Confirm to Continue, dan Authenticator terdaftar dengan secret yang diketahui aplikasi authenticator uji. Mekanisme seeding (endpoint atau skrip uji) disediakan tim FE/BE karena tidak didefinisikan di TC, PRD, atau LLD.

## Test Steps

### TC-AUTH-MFA-05: Screening halaman Authenticator Verification setelah Login with Password (tautan Use a different method tampil)

1. Buka halaman `Auth > Login with Password` di browser → halaman Login with Password tampil
2. Ketik `rizkypratama+{runId}-009@qwertysystem.net` pada field Email
3. Ketik `Spectra.env.MFA_PASSWORD` pada field Password
4. Centang widget reCAPTCHA "I'm not a robot"
5. Klik button [Log in] → halaman `Auth > MFA > Choose Verification Method` tampil
6. Pilih opsi "Authenticator app" pada halaman Choose Verification Method
7. Klik button [Login] → halaman `Auth > MFA > Authenticator Verification` tampil
8. Susuri halaman dari atas ke bawah tanpa mengklik apa pun
9. Verifikasi **Header**: Card `Elevated` terpusat
10. Verifikasi Logo TAG Samurai di bagian atas card
11. Verifikasi Title "Enter authenticator code"
12. Verifikasi Subtitle "Enter the 6-digit code generated by your authenticator app"
13. Verifikasi **Body**: SegmentedInput 6 kotak digit dalam dua grup tiga kotak
14. Verifikasi Keenam kotak digit kosong
15. Verifikasi Kursor aktif di kotak 1
16. Verifikasi Tidak ada area Resend dan tidak ada tautan recovery code
17. Verifikasi **Footer**: Button [Login] full-width (severity primary)
18. Verifikasi Button [Login] enabled
19. Verifikasi Button Text [Use a different method] di tengah (tampil karena faktor-1 = Password)

## Notes

- Sumber: `auth/mfa/TestCases/tc-mfa.md`. Subjudul `###` memetakan langkah ke id TC granular untuk report per langkah.
- Langkah pembuka tiap TC sesudah TC pertama menutup jendela user uji dari TC sebelumnya dan menghapus sesi login browser terkait (ID device dan jendela sesi akun aktor tetap) sebelum jendela baru dibuka; itu langkah penghubung tanpa `Verifikasi` (S-03, S-09).
- Urutan: TC-AUTH-MFA-103 dijalankan sebelum TC-AUTH-MFA-102 karena TC-AUTH-MFA-102 berakhir pada login sukses (membuat sesi web dan trusted device); screening dan validasi input yang tidak membuat sesi didahulukan (S-05, S-10).
- Langkah penghubung tanpa awalan `Verifikasi` (buka jendela privat baru di awal tiap TC kecuali TC pertama) bukan asersi tambahan (S-03).
- Ukuran spec (smell sekitar 35 langkah): spec ini sekitar 77 langkah setelah langkah prefix login faktor-1 yang identik (buka Login with Password sampai klik [Log in]) tidak dihitung. Tidak dipecah karena ketujuh TC independen: tiap TC memakai user dan jendela privat sendiri, sehingga bagian sesudahnya tetap bermakna bila bagian sebelumnya gagal.
- Verifikasi "tidak ada verifikasi otomatis berjalan" pada TC-AUTH-MFA-08, 101, 102 memakai pemantau request jaringan dan halaman yang tetap Authenticator Verification.
- Temuan untuk QA: (1) TC-AUTH-MFA-06 Langkah Uji 5 tidak memuat aksi submit dari halaman Verify OTP ke Authenticator Verification (hanya "Ketik 6 digit kode OTP"); spec mengikuti TC, halaman Authenticator Verification diasumsikan tampil setelah 6 digit terisi (S-15). (2) TC-AUTH-MFA-103 butir c ("Server menolak kode non-numerik yang lolos filter FE (diuji pada TC terpisah)") bukan hasil yang dapat diasersi dari langkah TC ini; tidak ada langkah `Verifikasi` untuk butir itu, dan kasusnya dirujuk ke TC-AUTH-MFA-104 (di luar spec ini). (3) Post Condition tanpa langkah observasi dan tanpa Expected padanan tidak diasersi (S-01): TC-AUTH-MFA-05 dan TC-AUTH-MFA-06 "Sesi pre-auth MFA aktif untuk `Rizky Pratama`" dan "... `Nur Hidayati`" (sesi pre-auth teramati sebagai halaman Authenticator Verification tampil pada Expected). TC-AUTH-MFA-102 Post Condition "Satu sesi web aktif untuk `Lina Rahmawati`" sama dengan klausa sesi pada Expected b dan diasersi lewat Expected tersebut. (4) Post Condition "Tidak ada entri log" pada TC-AUTH-MFA-08, 101, 103 tidak punya Expected padanan maupun langkah observasi di TC, dan TC itu tidak masuk spec absence; tidak diasersi di spec (S-01, S-05, S-15). QA perlu menambah Expected atau langkah observasi ke TC bila ketiadaan entri log itu harus diuji. (5) Pre-setup TC (#20/#21) belum memuat mekanisme seeding state BE per user (trusted device ber-ID device browser A, lokasi dan waktu login terakhir, secret authenticator yang dikenal authenticator uji, consent, logout web terakhir); mekanisme seed disediakan tim FE/BE.

# Suite: Admin Console TAG Stock

Suite ini mencakup halaman Admin Console > TAG > Stock: Stock List, Detail SKU (Tab Available dan Tab In Use, Summary bar, banner Waiting for Approval), Add Stock lewat scan (RFID, NFC, BLE) dan lewat Import atau Manual Entry (GPS), Duplicate Identifier Approval di Approvals > TAG Stock (Tab Active dan Tab History), Audit TAG (RFID dan NFC), Delete Unit (per unit, Bulk Delete, Delete by Scan), modal Event Log (Tab Add Stock dan Tab Audit TAG) beserta Popup Detail, Popup TAG Log, kontrol tabel (Search, Filter, Sort, Setup Column, Pagination, Download) pada enam permukaan, Role Matrix dan scope entitas (Principal dan Distributor), pencatatan System Log, Activity Log, dan Event Log, sinkronisasi lintas modul (Global Settings > All Tags, Device Allocation, Approvals, notifikasi), defense-in-depth, state tenant (Suspended), konkurensi, serta ketahanan terhadap kegagalan server.

`parallel: false` karena spec memakai atau mengubah state yang dipakai bersama: identifier TAG tetap (EPC, UID, MAC, IMEI Tabel Data Uji Dinamis) yang tidak dapat diberi suffix per run, Selection Limit, format tanggal General Settings, status Suspended entitas Distributor, toggle Local Registration Distributor, jam server dan jam browser, flag Guided Tooltip, simulator reader bersama (RFID, NFC, BLE, dan Handheld Reader HR-RFID-01), dan dataset volume (101 baris atau lebih, 1.001 TAG, 5.000 dan 5.001 baris). Setiap spec tetap menyiapkan dan memulihkan datanya sendiri lewat hook dan tidak bergantung pada hasil spec lain.

## Hook suite

- Login dan halaman: akun aktor pertama login di hook `before` spec (akun dan env dibaca dari `## Prerequisites` spec); hook `beforeEach` suite membuka TAG > Stock lewat sidebar kecuali spec menyatakan halaman awal lain di Prerequisites. `## Prerequisites` spec menulis "Login di hook `before` spec ini; halaman dibuka hook `beforeEach` suite". Spec yang selesai di akun lain memulihkan sesi ke akun default suite (Total Control) di hook `after`.
- Flag Guided Tooltip `guided_tooltip_seen_ac-tag-stock`: hook `before` suite mencatat nilai awal flag lalu menyetelnya `seen` (true) untuk setiap akun UI yang dipakai suite; hook `after` memulihkan nilai awal. Spec Guided Tooltip Stock List dan spec yang butuh flag belum `seen` mengatur flag sendiri sesudah hook dan menyebutnya di Prerequisites. Kemampuan membaca dan menyetel flag disediakan tim FE/BE.
- Jaring pengaman form dirty: hook `afterEach` suite mengonfirmasi dialog `beforeunload` dan menutup dialog `Unsaved Changes` yang tersisa. Ini bukan pengganti langkah pemulihan eksplisit di spec (S-09).
- Sesi API aktor: login API (password) untuk akun yang sama dengan sesi UI memakai token yang tidak dihitung sebagai sesi web, sehingga sesi UI tidak diusir. Kemampuan ini disediakan tim BE/FE; `## Prerequisites` spec merujuknya dengan satu baris. Pelaku kedua yang hanya memicu perubahan state (Admin B, Client Global Settings, Principal pengubah toggle) memakai sesi API ini; sesi UI kedua dipakai hanya pada spec konkurensi yang mengasersi hasil di sesi itu.
- Simulator reader: pemindai RFID, NFC, dan BLE (scan satu per satu, scan beruntun, kode tidak dikenal, pemutusan koneksi, dan beberapa reader sekaligus) serta Handheld Reader USB `HR-RFID-01` (terdeteksi di Sync Panel) disediakan tim FE sebagai simulator dan dinyatakan di `## Prerequisites` spec yang memakainya; mekanismenya tidak dikarang di spec. Spec yang memakai simulator berjalan serial.
- Koneksi simulator reader: hook `beforeEach` suite memulihkan koneksi simulator reader (RFID, NFC, BLE) sebelum tiap spec, sehingga spec tidak memuat langkah sambung ulang sendiri; spec yang memutus koneksi sebagai objek uji tetap menulis pemutusannya sebagai langkah uji, dan pemulihannya oleh hook ini (S-09). Kemampuan menyambungkan ulang disediakan tim FE sebagai bagian simulator.
- Fixture BE: seeding dan pemulihan SKU dan unit TAG (Available, Damaged/Missing, In Use, Combined, Waiting for Approval, Rejected), Subject Duplicate Identifier Approval (Register Duplicate dan Activation Collision), sesi Event Log, entri TAG Log, saldo Stock Ledger, Selection Limit, status Suspended entitas, toggle Local Registration, plan, dan pembacaan state BE yang tidak terlihat di UI disediakan tim FE/BE tanpa endpoint karangan di spec. Kemampuan baca atau seed yang tidak disebut TC, PRD, atau LLD dicatat di "Temuan untuk QA". Identifier tetap (EPC, UID, MAC, IMEI) bersifat tetap dan tidak bisa bersuffix `{runId}`: seeding idempotent dan pemulihan lewat fixture BE sebelum spec yang memakainya (S-12).
- Jam server dan jam browser: countdown, cooldown, dan boundary waktu dipenuhi dengan mengatur kedua jam bersama (bagian 6 konvensi), dipulihkan di hook `after`; waktu terbit artefak dibaca lewat API seeding.
- State global yang dipulihkan di hook `after` spec pemiliknya: Selection Limit (spec Bulk Delete seleksi dan limit), format tanggal General Settings (spec format tanggal lintas modul), status Suspended entitas Distributor (spec state tenant), toggle Local Registration Distributor (spec konkurensi toggle dan spec role/Request langsung toggle OFF), plan tier (spec Plan Gating), jam server dan jam browser, dan flag Guided Tooltip.
- Konfigurasi kolom Setup Column yang disimpan spec: hook `after` (dan `before`) spec pemiliknya menghapus preferensi kolom tabel di browser, bukan `[Reset to Default]` (bagian 4 konvensi; kemampuan disediakan tim FE).
- Data Pre-setup (Tabel Data Uji Pre-setup TC: SKU `RFID-ASSET-CORE-R5`, `NFC-CARD-BETA-N2`, `BLE-BEACON-ALPHA-B1`, `GPS-TRACK-CORE-G3`, `RFID-SEAL-DELTA-R1`, `RFID-PLAIN-X1`, `GPS-NEW-TEST-G9`, `RFID-TEMP-UJI-R9`, dan Handheld Reader `HR-RFID-01`) tidak dihapus oleh spec mana pun, kecuali SKU `RFID-TEMP-UJI-R9`: SKU sementara tanpa unit TAG ini dihapus oleh TC-AC-ACTS-720 di spec TC-AC-ACTS-E2E-056 (lewat sesi API aktor Admin lain) dan dibuat ulang hanya di hook `before` spec itu lewat fixture BE; spec lain tidak boleh bergantung pada keberadaan SKU tersebut sesudah spec 056 berjalan. Aksi tulis dan hapus memakai unit milik spec yang di-seed di hook `before` (S-06, S-12). Pengecualian S-06 (data tidak dapat dimiliki spec) ditulis di Prerequisites spec yang bersangkutan beserta pemulihan lewat fixture BE.
- Env var password akun aktor mengikuti `<APP>_<ROLE>_PASSWORD`: `AC_TC_PASSWORD` (Total Control), `AC_RO_PASSWORD` (Read Only), dan `AC_DU_PASSWORD` (Default User) dipakai juga suite Admin Console lain; nama baru untuk suite ini (`AC_TC2_PASSWORD`, `AC_AA_PASSWORD`, `AC_AA_CREATE_PASSWORD`, `AC_TS_CREATE_PASSWORD`, `AC_TS_UPDATE_PASSWORD`, `AC_TS_DELETE_PASSWORD`, `AC_TS_READ_PASSWORD`, `AC_DIST_ON_PASSWORD`, `AC_DIST_OFF_PASSWORD`, `AC_DIST_SUSP_PASSWORD`, `AC_DIST_NOROLE_PASSWORD`, `AC_ROLELAIN_PASSWORD`, `AC_PARTNER_PASSWORD`, `AC_CLIENT_PASSWORD`) ditetapkan penulis spec dan didaftarkan di `executionConfig.environmentVariables` dan `.env.example` oleh pemilik repo.

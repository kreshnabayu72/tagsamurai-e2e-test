# Suite: Admin Console Settings User

Suite ini mencakup halaman Settings > User: User List (Search, Filter, Sort, Pagination, Setup Column, Download, Sidebar Group, Guided Tooltip), Detail User (Tab Role Global Role dan Group Role, Popup Assign Group Role dan Select Group, Detail Group Assignment, Dialog Auto-Revert Tier, Tab Responsibilities, Tab Changelog, Tab System Log, Tab User Log), Modal Changelog User, Global Role, dan Group Role, aksi status (Activate, Deactivate, Bulk) dan Resend Email beserta cooldown, Role Matrix per aktor, state tenant (entitas Suspended), pencatatan di Changelog, System Log, dan Activity Log, notifikasi in-app ke target, sinkronisasi lintas modul (Role & Permission, Global Settings, Settings > Group, Custom Field User, General Settings), defense-in-depth, konkurensi dua aktor, ketahanan terhadap kegagalan server, serta aturan khusus mobile Android.

`parallel: false` karena spec mengubah atau memakai state global dan data bersama di entitas Principal: batas Selection Limit (Lifecycle Settings > System Limits), format tanggal General Settings, status Suspended entitas Distributor Nusantara, jam server dan jam browser untuk cooldown Resend 60 detik, flag Guided Tooltip, Custom Field User, dan aksi Select All yang mengenai seluruh user eligible di entitas. Setiap spec tetap menyiapkan dan membersihkan datanya sendiri lewat hook dan tidak bergantung pada hasil spec lain.

## Hook suite

- Login dan halaman: akun aktor pertama login di hook `before` spec; hook `beforeEach` suite membuka Settings > User lewat sidebar. `## Prerequisites` spec menulis "Login di hook `before` spec ini; halaman dibuka hook `beforeEach` suite". Spec yang selesai di akun lain memulihkan sesi ke Default User di hook `after`.
- Flag Guided Tooltip `guided_tooltip_seen_ac-settings-user`: hook `before` suite mencatat nilai awal flag lalu menyetelnya `seen` (true) untuk setiap akun UI yang dipakai suite; hook `after` memulihkan nilai awal. Spec yang menguji Guided Tooltip (009 dan 010) dan spec yang butuh flag belum `seen` mengatur flag sendiri sesudah hook dan menyebutnya di Prerequisites. Kemampuan membaca dan menyetel flag disediakan tim FE/BE.
- Jaring pengaman form dirty: hook `afterEach` suite mengonfirmasi dialog `beforeunload` dan menutup dialog `Unsaved Changes` yang tersisa. Ini bukan pengganti langkah pemulihan eksplisit di spec (S-09).
- Sesi API aktor: login API (password) untuk akun yang sama dengan sesi UI memakai token yang tidak dihitung sebagai sesi web, sehingga sesi UI tidak diusir. Kemampuan ini disediakan tim BE/FE; `## Prerequisites` spec merujuknya dengan satu baris. Pelaku kedua yang hanya memicu perubahan state memakai sesi API ini.
- Fixture BE: seeding dan pemulihan user (status aktivasi, Active/Inactive, role, group, tier, Group Manager), group tree, Custom Field User, entri System Log, Changelog, dan User Log, flag Guided Tooltip, Selection Limit, status Suspended entitas, serta pembacaan state BE tak terlihat di UI disediakan tim FE/BE tanpa endpoint karangan di spec. Kemampuan baca atau seed yang tidak disebut TC, PRD, atau LLD dicatat di "Temuan untuk QA".
- Jam server dan jam browser: cooldown Resend 60 detik (spec 039, 041, 165, 183, 185, 188, 191, 207; spec 188 memakai jam perangkat Android sebagai pengganti jam browser) dan bagian waktu lain dipenuhi dengan mengatur kedua jam bersama (bagian 6 konvensi), dipulihkan di hook `after`. Waktu terbit artefak dibaca lewat API seeding.
- Mail-catcher: kemampuan membaca jumlah email per alamat (baseline sebelum aksi) disediakan tim FE; hanya spec 183 yang memakainya. Spec Resend lain (039-041, 191) tidak membaca email.
- State global yang dipulihkan di hook `after` spec pemiliknya: Selection Limit (spec 033), Date Format General Settings (spec 076) dan format General Settings (spec 175), status Suspended entitas Distributor Nusantara (spec 042-044), jam server dan jam browser (lihat butir jam), Custom Field User milik spec yang dihapus atau dinonaktifkan (spec 091-092), dan flag Guided Tooltip (spec 009-010).
- Konfigurasi kolom Setup Column yang disimpan spec: hook `after` (dan `before`) spec pemiliknya menghapus preferensi kolom tabel di browser, bukan `[Reset to Default]` (bagian 4 konvensi; kemampuan disediakan tim FE). Spec yang menyimpan konfigurasi kolom: User List 074-078, 083-089, 091, 092, 194; Tab Responsibilities 096, 100, 101; Tab Changelog 110, 111; Modal Changelog User 129, 134-136, 198; Modal Changelog Global Role 142, 143, 206; Modal Changelog Group Role 151, 152.
- Data Pre-setup (Tabel Data Uji Pre-setup TC, termasuk user target DS-UL, Group Tree, dan Custom Field bawaan) tidak diubah atau dihapus oleh spec mana pun kecuali pengecualian S-06 `[KEPUTUSAN 2026-10-30]` di bawah; aksi tulis dan hapus memakai data milik spec yang di-seed di hook `before` dengan suffix `{runId}-<NNN>` (S-06, S-12).
- Pengecualian S-06 `[KEPUTUSAN 2026-10-30]` (data Pre-setup tidak dapat dimiliki spec): akun aktor dan baris yang dipakai login atau diasersi sebagai Pre-setup diubah sementara lewat Fixture BE: status aktivasi dan status email baris Default User entitas Principal (Pre-setup #1) dan akun aktor Total Control (Pre-setup #2) pada spec 006 (TC-11, 12), Group Role aktif pada Default User dan akun Total Control pada spec 023 (TC-68), Group Role akun Manage user and role (Pre-setup #4) pada spec 022 (TC-78), email pending akun Manage user and role (Pre-setup #4) pada spec 024 (TC-140), dan status Pending Email Confirmation Default User (Pre-setup #1) pada spec 038 (TC-141). Pemulihan ke keadaan awal dijamin Fixture BE (disediakan tim FE/BE; idempotent) dan dijalankan di hook `before`, di antara blok TC, dan di hook `after`; efek pada Last Update, Modified By, dan entri audit trail dicatat di `## Prerequisites` spec pemiliknya; suite berjalan serial.
- Spec Android (188) memakai perangkat fisik bersama dan menulis `parallel: false` di `## Prerequisites`.
- Env var password akun aktor mengikuti `<APP>_<ROLE>_PASSWORD`. `AC_TC_PASSWORD` (Total Control) sudah terdaftar di `executionConfig.environmentVariables`; `AC_RO_PASSWORD` (Read Only) dan `AC_DU_PASSWORD` (Default User) dipakai juga suite Admin Console lain tetapi belum terdaftar di sana. Nama yang ditetapkan penulis spec dan didaftarkan di `executionConfig.environmentVariables` dan `.env.example` oleh pemilik repo: `AC_MUR_UPDATE_PASSWORD` (Manage user and role Update), `AC_MUR_READ_PASSWORD` (Manage user and role Read saja), `AC_GM_PASSWORD` (Group Manager tanpa akses modul), `AC_TS_PASSWORD` (Manage TAG stock saja), `AC_DIST_TC_PASSWORD` dan `AC_DIST_MUR_PASSWORD` (Total Control dan Manage user and role Update entitas Distributor Nusantara), `AC_E1_TC_PASSWORD` dan `AC_E1_DU_PASSWORD` (Total Control dan Default User entitas baru E1), serta `AC_SU_SEEDED_PASSWORD` (password user target hasil seeding). Password tidak ditulis di spec atau fixture.

# Suite: Admin Console Activity Log

Suite ini mencakup halaman Activity Log Admin Console yang read-only: Tab Session dan Tab User Action (tabel, Search, Filter Panel, Sort, Setup Column, Pagination, Download), isi kolom per tab, snapshot beku, Role Matrix, isolasi scope entitas (Principal, Distributor, Partner), Guided Tooltip, format tanggal dan bahasa, sinkronisasi real-time, State tenant, defense-in-depth, volume besar, serta ketahanan terhadap kegagalan server.

`parallel: false` karena spec mengubah state global bersama (flag Guided Tooltip, preferensi kolom Setup Column di browser, Reassign Partner, perpindahan staf, status Suspended entitas, General Settings tanggal, zona waktu, dan bahasa, serta volume seed log) dan memicu aksi di modul sumber yang menambah baris log. Spec yang menghapus data sumber atau mengubah hubungan entitas (Reassign, hapus Brand `Acme {runId}-045`, pindah `Tono`, hapus `Rudi {runId}-046` dan `Bayu`) sebaiknya dijalankan paling akhir. Setiap spec tetap menyiapkan dan membersihkan datanya sendiri lewat hook dan tidak bergantung pada hasil spec lain.

## Hook suite

- Login akun aktor suite: Total Control (Principal) `totalControlAdminConsole_automated_{namaCompany}@qwertysystem.net` (Pre-setup No 1 TC), `Spectra.env.AC_TC_PASSWORD`, dilakukan di hook `before`; hook `after` mengembalikan sesi ke akun itu. `AC_TC_PASSWORD` (Total Control Admin Console) sudah terdaftar di `executionConfig.environmentVariables` (`spectra.config.ts`) dan `.env.example`; password akun lain (Read Only, Default User, Group Manager, Distributor, Partner) memakai nama `AC_<ROLE>_PASSWORD` yang ditetapkan tim FE. Email akun memuat placeholder `{namaCompany}` di Pre-setup TC.
- Halaman: hook `beforeEach` membuka Admin Console > Activity Log (tab Session). Spec yang tidak menguji navigasi tidak mengulang langkah buka di `## Test Steps`.
- Guided Tooltip: hook `before` mencatat nilai awal flag `seen` halaman Activity Log (`page_key` `ac-activity-log`; nama flag usulan `guided_tooltip_seen_ac-activity-log`, dikonfirmasi tim FE/BE) untuk akun aktor yang dipakai suite lalu menyetelnya ke true lewat API; hook `after` memulihkan nilai awal. Spec yang login dengan akun lain menyetel dan memulihkan flag yang sama untuk akun itu di hook `before`/`after` spec-nya, dan spec yang membuka halaman lain menyetel flag halaman tujuan dengan cara yang sama; keduanya ditulis satu baris di `## Prerequisites` spec yang bersangkutan. Spec yang bukan spec Guided Tooltip merujuk hook ini dengan satu baris; spec 006 dan 007 mengatur flag sendiri sesudah hook.
- Setup Column: hook `after` menghapus preferensi kolom Setup Column di browser (bukan `[Reset to Default]`; kemampuan disediakan tim FE) untuk spec yang menyimpan konfigurasi kolom, yaitu spec Setup Column kedua tab dan spec yang menyembunyikan kolom yaitu spec 026, 027, 032, 033 dan spec lain yang menyembunyikan atau mengurutkan kolom (023, 036, 039, 040, 051, 054).
- Pengecualian `beforeEach`: spec 013 (akun tanpa akses Activity Log) tidak dibuka ke Activity Log oleh hook `beforeEach` suite; spec itu memakai halaman awal akun yang bersangkutan (kemampuan melewati hook disediakan tim FE). Spec lain tetap memakai `beforeEach` suite.
- Env password yang dirujuk spec (disediakan tim FE; `.env.example` dan `spectra.config.ts` tidak diubah di sini). Terdaftar di `.env.example` dan `spectra.config.ts` (hasil grep): hanya `AC_TC_PASSWORD`; semua nama AC_* lain di bawah adalah nama usulan tim FE dan belum terdaftar di keduanya. Akun aktor: `AC_TC_PASSWORD` (Total Control Principal, 001-055 kecuali 011, 013, 016, 019, 037, 039, 041, 042); `AC_RO_PASSWORD` (Read Only, spec 007, 012); `AC_DU_PASSWORD` (Default User, 012); `AC_GM_PASSWORD` (Group Manager, 013, 020); `AC_FULLCRUD_PASSWORD` (Capability Client Full CRUD, 013, 020); `AC_GSONLY_PASSWORD` (020); akun Total Control per entitas: `AC_ALFA_TC_PASSWORD` (014-020, 037, 044-046), `AC_BETA_TC_PASSWORD` (014-016), `AC_GAMMA_TC_PASSWORD` (014, 018), `AC_DELTA_TC_PASSWORD` (014), `AC_SEJAHTERA_TC_PASSWORD` (013), `AC_LIMITLOG_TC_PASSWORD` (039), `AC_VOLUME_TC_PASSWORD` (041, 042); `AC_PRINCIPAL_SEGAR_PASSWORD` (043, akun Principal segar per run untuk TC-166); Read Only per entitas: `AC_ALFA_RO_PASSWORD`, `AC_BETA_RO_PASSWORD` (016); password staf dan admin dinamis bersuffix: `AC_DYN_PASSWORD` (015-017, 019-022, 024, 030, 043-046).

Selain `AC_TC_PASSWORD` (sudah terdaftar), tim FE mendaftarkan nama-nama lain di set ini di `executionConfig.environmentVariables` dan `.env.example`.
- Fixture: `Fixture.activityLog.*` yang dirujuk spec mengacu ke berkas fixture baru `fixtures/activityLog.json` yang disediakan tim FE (nilainya mengikuti Pre-setup dan Data Dinamis TC); berkas itu belum dibuat.
- Sesi API aktor (bagian 5 konvensi): login API (password) untuk akun yang sama dengan sesi UI memakai token yang tidak dihitung sebagai sesi web, sehingga sesi UI tidak diusir. Dipakai spec yang membutuhkan pelaku kedua (aksi modul sumber, Unsuspend, Reassign) tanpa konteks UI kedua. Kemampuan disediakan tim BE/FE.
- Seeding data log: mekanisme seeding entri Session dan User Action (stempel waktu yang dapat ditentukan, termasuk stempel identik, volume 35, 5.000, 5.001, 10.000 ke atas, dan 1.048.577 entri, serta snapshot identitas) tidak didefinisikan di TC, PRD, atau LLD yang dibaca; kemampuan itu disediakan tim FE/BE dan dicatat di "Temuan untuk QA" tiap spec yang memakainya. Tidak ada endpoint karangan di spec. Entri log bersifat audit trail permanen sehingga seed tidak dihapus dan total entri tidak diasersi sebagai angka absolut (S-12).
- Kemampuan lain yang disediakan tim FE dan dirujuk spec: intercept dan penahanan respons HTTP (list, options, export, stream), mengatur jam server dan jam browser, network offline, inspeksi koneksi stream, membaca isi berkas CSV/XLSX, membaca jumlah entri sebelum aksi (baseline), dan pemulihan state (status entitas, hubungan Partner, posisi staf, bahasa, General Settings).
- Urutan jalan (rekomendasi eksekusi): spec yang mengubah hubungan entitas atau menghapus data sumber (Reassign Partner, pindah `Tono`, hapus Brand `Acme {runId}-045`, hapus `Rudi {runId}-046` dan `Bayu`) sebaiknya dijalankan paling akhir; nomor folder disusun menurut urutan itu, tetapi runner belum terbukti mengikuti nomor folder (bagian 3), sehingga tiap spec tetap mandiri dan tidak bergantung pada urutan.

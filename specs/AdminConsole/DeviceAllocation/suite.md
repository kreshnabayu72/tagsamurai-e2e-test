# Suite: Admin Console Device Allocation

Suite ini mencakup halaman Device Allocation: List (Search, Filter, Sort, Pagination, Setup Column, Download), panel Stock Balance, modal Allocation Log, form Allocate (validasi, preview biaya, submit jalur langsung dan jalur persetujuan), Edit, Cancel, Resubmit, Approve/Reject di Approvals, Timeout dan peringatan H-24, Role Matrix, scope, state tenant, pencatatan Activity Log dan System Log, notifikasi, format tanggal General Settings, defense-in-depth, multi-konteks, resilience, atomisitas, dan plan gating.

`parallel: false` karena spec memakai state global bersama: saldo wallet dan Reserved entitas, kuota Client, stok, nomor urut Allocation ID per tanggal, General Settings (Date/Time Format), preferensi Setup Column per browser, jam server, dan job Timeout. Setiap spec menyiapkan dan memulihkan datanya sendiri lewat hook; transaksi yang dibuat spec tidak dapat dihapus lewat UI, sehingga hook `after` memulihkan seed lewat kemampuan fixture Pre-setup #20 yang disediakan tim FE/BE (termasuk membatalkan transaksi Waiting for Approval milik spec 020).

## Hook dan kemampuan suite

Bagian ini adalah satu-satunya tempat pernyataan hook suite; `## Prerequisites` tiap spec merujuk ke sini dan hanya menambah kebutuhan spesifik spec.

- Sesi API aktor: setiap spec dapat membuka sesi API atas nama akun aktor (dan akun pelaku kedua yang disebut spec) dengan password dari `Spectra.env.*`. Sesi ini dipakai untuk membaca state (saldo, Reserved, kuota, status, jumlah entri log, jumlah notifikasi) dan memicu aksi pelaku kedua (Approve, Reject, Cancel) tanpa konteks UI kedua; sesi API tidak menampilkan toast sehingga langkah pemicu ditulis "... hingga ... tersimpan". Kontrak endpoint disediakan tim FE/BE dan tidak dikarang di spec.
- Flag Guided Tooltip: hook `before` menyetel flag `guided_tooltip_seen_<page_key>` (untuk halaman ini `guided_tooltip_seen_ac-device-allocation`) menjadi true bagi akun aktor agar tooltip tidak menutupi halaman; hook `after` memulihkan flag ke nilai awal.
- Preferensi Setup Column: preferensi kolom disimpan per browser dan per akun. Hook `after` menghapus preferensi kolom akun aktor sehingga spec berikutnya mulai dari kolom default. Spec yang mengasersi kolom bawaan non-default menampilkannya lewat Setup Column pada langkah penghubung, dan menampilkannya ulang sesudah setiap ganti akun karena cakupan preferensi lintas akun tidak diasumsikan.
- Seed 30 baris: Seed List 30 baris (Pre-setup #48) disediakan fixture backend tim FE/BE dan idempotent (dilewati bila sudah ada), sesuai Lampiran A butir A-11. Hook `after` memulihkan seed ke 30 baris lewat fixture Pre-setup #20: hanya transaksi yang dibuat spec (Notes bersuffix `{runId}`) yang dibatalkan atau dipulihkan; baris seed tidak diubah permanen. Nilai literal `Batch lama`, `Batch uji`, dan `Stok belum siap` mengikuti A-11.
- Fixture Pre-setup #20 (disediakan tim FE/BE): menyetel saldo kantong, Reserved, dan kuota; membaca status, Reserved, kuota, notifikasi, dan jumlah entri log; membuat salinan transaksi Pre-setup #49 per spec; menggeser dan memulihkan jam server; mengatur status entitas dan Client; mengatur hak role; General Settings; fault injection. Kemampuan tiap spec ditulis di `## Prerequisites` spec itu.
- Fixture perubahan Pre-setup bersama untuk spec 053: rename Client #7, Partner #4, Distributor #3, perubahan nama user #32, toggle Require Approval for Allocation, keanggotaan Group Manager, dan harga RFID. Fixture menyimpan nilai awal dan memulihkannya di hook `before` dan `after` spec 053 (idempotent); efek ke Last Updated dan audit trail ditulis di `## Prerequisites` spec 053.
- Jam server digeser: spec yang menggeser jam server (004, 014, 015, 021, 030, 035, 046, 047, 052, 057) memakai pernyataan ini: sesi UI dan sesi API tetap valid selama jam server digeser, dan jam dipulihkan segera setelah job selesai serta di hook `after`. Pergeseran jam membatalkan semua transaksi Waiting for Approval yang melewati batas Approval Timeout, termasuk salinan milik blok lain, sehingga blok yang menggeser jam diletakkan di akhir spec, kecuali baseline dipulihkan fixture, dan asersi memakai Allocation ID.
- Transaksi Pre-setup bersama yang diubah langsung spec: transaksi #49, #52, #56, dan #57 yang diubah oleh spec 004, 014, dan 015 (status, Quantity, Notes, Reserved, atau pembatalan Timeout) dipulihkan fixture Pre-setup #20 ke baseline di hook `before`, hook `after`, dan langkah penghubung antar blok (Lampiran A butir A-11, syarat tambahan). Pre-setup #60 dan #68 diubah spec 010 dan dipulihkan fixture ke baseline di hook `before` dan hook `after`, tanpa langkah penghubung karena tiap transaksi hanya diubah satu blok (lihat `## Prerequisites` spec 010). Pre-setup #50 dan #70 (transaksi MB_P2 milik CV Karya Mandiri) disingkirkan fixture dari scope baca CV Karya Mandiri oleh spec 002 dan 016 (kondisi data TC-6 dan TC-120), lalu dipulihkan fixture ke baseline di hook `after` (lihat `## Prerequisites` spec 002 dan 016). Kemampuan pemulihan ini ditulis di `## Prerequisites` spec yang bersangkutan.

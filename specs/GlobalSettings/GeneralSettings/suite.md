# Suite: Global Settings General Settings

Suite ini mencakup halaman form satu record Global Settings > General Settings: screening dan nilai tersimpan, tooltip ikon info, opsi dan Select Searchable (Currency Code, Time Zone, Date Format, Time Format, Session Idle Timeout), Preview live, Save per field dan multi-field, dialog Change Currency dan Unsaved Changes, Guided Tooltip, Role Matrix (Total Control, Read Only, akses ditolak), state tenant (Suspended, Expired, plan tier), Session Idle Timeout dengan manipulasi jam, Modal Changelog (screening, Search, Filter, Sort, Setup Column, Download, Pagination, kombinasi), pencatatan log di Changelog dan Activity Log serta asersi absence, multi-konteks (kebijakan satu sesi web, propagasi SSE ke tab lain, dua admin, dua tenant), format timestamp lintas modul, defense-in-depth (RBAC dan payload PUT langsung, bypass klien lewat DOM), ketahanan terhadap kegagalan server (baca, Save, Changelog), serta tampilan mobile Android.

`parallel: false` karena satu record General Settings per entitas dipakai bersama seluruh spec dan spec mengubah state global: format tanggal, Time Zone, dan Currency Code entitas (dibaca juga oleh suite Global Settings lain), flag Guided Tooltip, jam server dan jam browser (spec 024), status Client dan plan (spec 021 sampai 023), kuota sesi web (spec 025), konfigurasi kolom Modal Changelog (spec 028, 032, 035, 036, dan 054), lebar viewport (spec 010, 031, 035), dan perangkat atau emulator Android bersama (spec 012 dan 013). Setiap spec tetap menyiapkan dan membersihkan datanya sendiri lewat hook dan tidak bergantung pada hasil spec lain. Changelog dan Activity Log adalah audit trail permanen dan setiap Save menambah entri, sehingga total entri tidak pernah diasersi sebagai angka absolut: spec memakai baseline jumlah sebelum aksi atau pencarian berbasis Field, Old Value, dan New Value.

## Hook suite

- Flag Guided Tooltip `guided_tooltip_seen_gs-general-settings` (page_key `gs-general-settings`, PRD §4.7): hook `before` suite mencatat nilai awal flag lalu menyetelnya `seen` (true) untuk setiap akun UI yang dipakai suite, dan hook `after` memulihkan nilai awal. Hook ini berlaku untuk akun aktor default (Total Control Client A, Budi Santoso, `Spectra.env.GS_TC_PASSWORD`) dan untuk setiap akun lain yang dipakai spec: Read Only, System Role, dan Capability Individual (Pre-setup No 3, 5, 4), Total Control kedua Client A (Andi Wijaya, Pre-setup No 2, sesi UI kedua di spec 045), serta akun staf entitas lain yang disediakan tim FE: Client Baru dan Client Negara Lain (spec 005), Client Tanpa Record (006), Client Suspended dan Client Expired (021, 022), Client Starter, Growth, Professional, dan Enterprise (023), Client Satu Riwayat (029), Client Lain (046), serta PT Maju Bersama dan PT Sentosa Abadi (047). Kemampuan membaca dan menyetel flag disediakan tim FE/BE (tidak ada endpoint di TC, PRD, atau LLD); nama endpoint tidak dikarang. Spec yang menguji flag atau tidak memakai hook web suite menulis pengaturan flag-nya sendiri di `## Prerequisites`: spec 009 dan 010 (Guided Tooltip), serta spec mobile 012 dan 013. `## Prerequisites` spec lain merujuk pernyataan ini dengan satu baris.
- Baseline record Client A (Pre-setup No 10: Currency Code `IDR`, Date Format `dd/MM/yy`, Time Format `HH:mm`, Time Zone `Asia/Jakarta`, Session Idle Timeout `30 minutes`): hook `beforeEach` suite memulihkan record ke baseline lewat PUT `/v2/enterprise-management/general-settings` (`global-settings/general-settings/API/openapi.yaml`) memakai sesi API Total Control Client A (klien HTTP dan penangkapan token sesi API disediakan tim FE; token sesi API tidak dihitung sebagai sesi web, sehingga batas satu sesi web dan sesi UI Total Control Client A tidak terpengaruh), dan hook `after` suite memulihkan ulang walau spec gagal di tengah. Entri Changelog dan Activity Log yang bertambah karenanya tidak dihapus. Pemulihan ini hanya untuk entitas Client A; spec yang bekerja pada entitas lain (005, 006, 021, 022, 023, 029, dan sisi Client Lain di 046) menyatakan baseline dan pemulihan entitas itu sendiri di `## Prerequisites`, dan reset entitas ke keadaan awal (Client Baru, Client Negara Lain, Client Tanpa Record, Client Satu Riwayat) disediakan tim FE/BE.
- Layar awal: hook `beforeEach` suite membuka Global Settings > General Settings (platform spec: web, atau aplikasi Android untuk spec 012 dan 013) untuk akun yang login di hook `before` spec itu, sehingga spec yang tidak menguji navigasi tidak mengulang langkah buka. Pengecualian, `beforeEach` tidak membuka General Settings: spec 008 (kedua role tidak berhak membuka halaman; precondition TC adalah berada di Global Settings), spec 022 dan 023 (halaman awal Global Settings; membuka General Settings adalah langkah 1 spec, objek uji), dan spec 047 (`beforeEach` membuka Admin Console > Client List sesuai precondition TC-GS-GSET-122, bukan General Settings).
- Login: akun aktor pertama tiap spec login di hook `before` spec itu (akun dan env var tertulis di `## Prerequisites` spec); langkah login di `## Test Steps` hanya untuk ganti akun, dan hook `after` spec mengembalikan sesi ke akun default suite.
- Konfirmasi bawaan browser `beforeunload`: reload atau navigasi pada form yang masih berisi perubahan belum tersimpan memunculkan konfirmasi bawaan browser. Kemampuan menanganinya (konfirmasi otomatis oleh harness, tanpa langkah bersyarat) ditulis di `## Prerequisites` spec yang membutuhkannya: spec 016, 020, 021, 051, dan 052 mengonfirmasi (reload dilanjutkan), sedangkan spec 019 membatalkan dialog (halaman tetap terbuka) pada TC-GS-GSET-52. Hook `beforeEach` suite menjadi jaring pengaman: ia mengonfirmasi `beforeunload` dan menutup dialog `Unsaved Changes` bila spec sebelumnya berakhir dengan form dirty; itu bukan pengganti langkah pemulihan eksplisit di spec yang mengubah form.
- Baris Changelog yang diasersi spec Changelog (026 sampai 040, 053, dan 054) di-seed lewat PUT API di hook `before` spec itu dengan nilai distinct per kolom yang di-search, difilter, atau di-sort; entitas yang sengaja berjumlah tepat satu baris (Client Satu Riwayat, spec 029) dikembalikan tim FE/BE sebelum tiap run. Konfigurasi kolom Modal Changelog yang disimpan spec 028, 032, 035, 036, dan 054 dipulihkan di hook `after` spec itu dengan menghapus preferensi kolom di browser (bukan `[Reset to Default]`); kemampuan itu disediakan tim FE.
- Akun di luar Tabel Data Uji Pre-setup TC (staf tiap entitas selain Client A) dan semua nama env var password baru ditulis "disediakan tim FE" di `## Prerequisites` spec yang memakainya; pendaftaran env var di `spectra.config.ts` dan `.env.example` dikerjakan di tahap script.
